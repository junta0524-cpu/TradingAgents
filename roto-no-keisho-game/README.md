# ロトの継承 ― RPG(全16章版)

『ロトの継承』の設定資料一式(シナリオ資料集・群像譜・魔物図鑑・宝物庫・地誌譜)を土台にした、ブラウザで動くRPGです。ビルド不要・依存ライブラリなしの素のHTML/CSS/JavaScriptで実装しています。シナリオ資料集と同じボリューム――**序章+全14章+終章の16章、全13ロケーション、モンスター全60種、パーティ4人**――をそのままゲームに組み込んでいます。

## 遊び方

このフォルダ内で簡易サーバーを立てて `index.html` を開いてください(`file://` 直開きよりローカルサーバー経由を推奨します)。

```bash
cd roto-no-keisho-game
python3 -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

操作:矢印キー / WASD で移動、Z または Enter で決定・メニュー開閉、X または Esc でキャンセル。

**スマホ・タブレット**では、画面下に十字キーと「けってい / もどる」ボタンが自動で出ます(指で操作する端末を検出したときだけ表示され、マウス環境には出ません)。画面幅に合わせてゲーム画面も縮みます。

## 実装した範囲

- **全16章のシナリオ進行**(序章 → 第一〜十四章 → 終章)。**章ごとに目的がある**:誰と話すか、魔物を何体退けるか、どのボスを倒すか。条件を満たすまで門は開かず、何が足りないのかを教えてくれる
  - **いま何をすべきかが 常に画面に出る**。「城の者たちと 話してから 城を出る (あと 2人と 話す)」のように、残りの数まで出す
  - **5つの分かれ道**。ガロズを赦すか討つか、ロトの遺産を三国に分けるか一箇所に集めるか、バロウズを疑うか信じるか、ガライを守るか退けるか、百年のどの場面を語り継ぐか
  - 選んだ結果は**セーブに残り、終章の式典の描写に返ってくる**。ガライを退ければ彼は仲間にならず、三人のまま旅が続く
- **全13ロケーション**(街5・フィールド3・ダンジョン5)。**一枚ずつ形が違う**。街道は森を縫い、平原は湖を回り込み、断崖は桟道が折り返す。ダンジョンも野営地・四層の塔・格子状の納骨堂・地底湖の洞窟・渦を巻く回廊とそれぞれ別構造。街も城/十字路の城塞都市/泉を囲む回廊/円形の広場/岩棚の集落と描き分けている
- **画面より大きいマップはスクロール**する。主人公を追って視界が動き、端まで来ればそこで止まる(街のように小さいマップは今までどおり中央に置く)
- **モンスター全60種**(雑魚54種+ボス5体、種族ごとに階層値からステータスを算出)。ロケーションごとの出現テーブルも自動生成
- **パーティ4人**(ロト・エルロード・セレスティア・ガライ)。シナリオの節目で自動的に仲間になり、戦闘は全員ぶん順番にコマンドを選ぶ方式
- **属性と耐性**:呪文には炎・氷・イオ・風・光の属性があり、魔物図鑑の9系統それぞれに通り方が違う。植物は炎に焼かれ(×1.8)風を受け流し(×0.6)、アンデッドは光に灼かれ(×1.8)眠らず(状態異常×0.4)、古代文明の石像は打撃を弾く(物理×0.6)。戦闘中は「弱点を ついた!」「しかし 効果は うすい……」と手応えが返る
- **章をまたいでも消耗は残る**:章の開始で全回復はしない(倒れた仲間だけ最低限で立ち上がる)。**HPとMPを全快させるのは宿屋だけ**なので、宿と道具に使う理由が生まれる
- **呪文・特技は全35種**。ドラクエの呪文表にならって、攻撃(メラ/ギラ/ヒャド/イオ/バギ/デインの各系統)・回復(ホイミ/ベホイミ/ベホマラー/キアリー/キアラル/ザオラル)・補助(スカラ/バイキルト/ピオリム)・弱体(ルカニ/ボミオス/ラリホー/マヌーサ/メダパニ)・旅の呪文(リレミト/トヘロス)を揃えている
  - **補助と弱体は戦闘のあいだだけ効く倍率**として乗る。バイキルトでこうげき力が上がり、ルカニで相手のしゅび力が下がる
  - **魔物にも状態異常がかかる**。ラリホーで眠らせ、マヌーサで攻撃を外させ、メダパニで同士討ちさせられる。ボスには効きにくい
  - **フィールドでも呪文が使える**。パーティメニューの「じゅもん」から、回復・解毒・蘇生・リレミト(入り口へ戻る)・トヘロス(弱い魔物が寄ってこなくなる)を唱えられる
- **ドラクエ式のコマンド戦闘**:全員のコマンドを決めてから、味方も魔物も混ぜて**すばやさの速い順に解決**する。コマンドは たたかう / じゅもん / **ぼうぎょ** / どうぐ / にげる
  - **ぼうぎょ** ― そのラウンドの被ダメージが半分。選んだ瞬間から効くので、後攻でも守れる
  - 狙っていた魔物が先に倒れたら、空振りせず残りへ向かう
  - **手負いの雑魚は逃げ出す**ことがある(最後の1匹は逃げない)。逃げられた分の経験値は入らない
  - ボスの全体攻撃技、道具のターゲット選択(誰に使うか選べる)
- **敵は群れで出る**:弱い魔物ほど数を揃え、ときどき別種が混ざる(「あかスライムと野良ゴブリンが あらわれた!」)。同名が並ぶときは A/B/C を添えて区別する
- **宝箱**:5つのダンジョンに計19個。中身は お金 / 道具 / 装備 で、奥へ行くほど良くなる。開けた箱は記録され、セーブにも残る
- **呪文はレベルで覚える**:最初から全部使えるわけではなく、レベルアップ時に「〜を おぼえた!」と増えていく
- **全滅すると所持金が半分**になる(DQの慣例)。HP/MPは3割回復してマップ入口から再開
- **街の施設**:道具屋(道)・武器防具屋(武)・宿屋(宿)・教会(教)。街のタイルを踏むと開き、品揃えは街ごとに異なる
- **仲間が隊列でついてくる**:2人目以降は先頭が通ったマスを1歩ずつ遅れて辿ります。先頭の足跡をそのまま歩くので、壁に入り込むことがありません。手前(画面の下)にいる者ほど後に描かれるので、重なりも正しく見えます
- **歩行アニメの受け口**:`assets/chars/<id>_walk_down.png` のような3コマのシートを置くと、その人物のその向きだけ歩き出します。左向きは横向きの絵を左右反転して使うので、向きは前・後ろ・横の3枚で足ります。まだ無い向きは立ち絵のまま表示されます
- **街の人々との会話**:王(王)と町人(紫)に話しかけられます。台詞は**章ごとに変わり**、同じ人物でも建国前と百年後では違うことを言います。ラダトーム王との謁見は、王位を辞して旅立つまでの一場面として進みます。まだ仲間になっていない人物は、その街には居ないものとして扱われます
- **ドラクエ式のステータス**:こうげき・しゅび・すばやさに加えて **まりょく** と **うんのよさ** を持つ
  - **まりょく** ― 呪文(メラ/メラゾーマ/ホイミ)の威力と回復量を決める。武技(なぎ払い・月光の矢など)はこれまでどおり こうげき力で殴るので、杖は「殴る武器」ではなく「唱えるための武器」になった
  - **うんのよさ** ― 状態異常を弾く確率(最大3割)と、**かいしんの一撃**の出やすさ。会心は相手のしゅび力を無視して大きく入る
  - レベルアップの伸びはキャラごとに違う。ガライは HP と ちから、エルロードは MP と まりょく が大きく伸びる
- **どうぐ袋**:パーティメニューの「どうぐ」から、拾った道具をフィールドでも使える。やくそう・せいすい・フェニックスの雫は誰に使うか選べ、帰還の羽根はそのマップの入り口まで一気に戻る
- **装備システム**:武器/よろい/たて/かぶと/そうしょくひんの5部位。装備がこうげき・しゅび・すばやさ・まりょく・うんのよさに直接反映され、キャラごとに装備できる種別が決まっている(杖使いは盾を持てない等)
- パーティメニューからの装備の付け替え、DQ的な温情リスポーン(全滅してもHPが少し残った状態で継続)
- **セーブ/ロード**:パーティメニューから「ぼうけんのしょに きろくする」で保存。章の節目では自動保存も入る。タイトル画面に「つづきから」と進行状況が出る(保存先はブラウザの localStorage)
- **状態異常**:どく・ねむり・こんらんの3種。魔物図鑑で「毒を撒く」「眠りの種」などと書かれている13種の魔物が実際に仕掛けてくる
  - **どく** ― ラウンド終了ごとにダメージ。戦闘後も残り、8歩ごとに体力を削る(歩いて死なないよう HP1 で止まる)
  - **ねむり** ― 手番を飛ばされる。毎ターン一定確率で目を覚ます
  - **こんらん** ― 対象を選べず、敵味方かまわず殴る
  - 治療は どくけし草(毒)/ めざめの葉(眠り・混乱)/ せいすい(すべて)。加護の護符は次の1回だけ状態異常を防ぐ。宿屋・教会・章の休息でも回復する

## フォルダ構成

```
index.html              エントリーポイント(canvas + script読み込み)
css/style.css           最小限のページスタイル
js/data/                 設定資料から落とし込んだゲームデータ
  characters.js          群像譜・宝物庫 → プレイアブル4人のステータス・スキル・装備
  monsters.js             魔物図鑑 → 全60種の敵データ・出現テーブル・ボス
  items.js                 宝物庫 → 消耗品(全9種)
  equipment.js              宝物庫 → 武器・防具・装飾品
  shops.js                   街ごとの品揃えと宿代・蘇生費用
  npcs.js                     王・重臣・町人の会話(章ごとに差し替わる)
  treasures.js                 宝箱の中身
  maps.js                     地誌譜 → 全13ロケーションのタイルマップ(1枚ずつ形を描き分けている)
  chapters.js                  シナリオ資料集 → 全16章の進行データ
js/engine/                汎用エンジン部分(ゲーム固有ロジックを含まない)
  input.js                 キー入力管理(仮想ボタンからの入力もここへ流す)
  touch.js                  スマホ用の仮想パッド(DOM とスタイルを自前で組み立てる)
  renderer.js              タイル・パネル・文字・ゲージの描画部品
  game.js                   モード切替(タイトル/フィールド/戦闘/エンディング)とメインループ
js/systems/                ゲーム固有システム
  party.js                  パーティの実行時ステータス管理・仲間加入
  dialogue.js                メッセージウィンドウ
  battle.js                   パーティ全員ぶんのコマンド式バトルシステム
  field.js                     フィールド移動・エンカウント・門/ボス床/施設/NPC判定
  menu.js                       パーティメニュー(状態確認・どうぐ袋・装備の付け替え)
  shop.js                        道具屋・武器防具屋・宿屋・教会
  save.js                         ぼうけんのしょ(localStorage への保存・復元)
  story.js                         全16章の章・ステージ進行管理
js/main.js                起動処理
```

データはすべて `Game.Data.*` に集約しているので、内容を調整する際は `js/data/` 配下のオブジェクトを編集するだけで反映されます。

## プレースホルダーの範囲(後から差し替え可能)

キャラクター絵・マップのタイル絵・BGMは、いずれも「後から組み込む」ことを前提にした造りです。**届いた絵から順に差し替えられる**ようになっており、まだ無いものは色面のまま表示されます(`js/engine/assets.js` が読み込みに失敗した素材を黙って無視します)。

現在入っている絵:`assets/tiles/` に草原・街道、`assets/chars/` にロト・エルロード・セレスティア・ガライ・王。人物は32×48で、足元をマスの下端に合わせて描いています(1マスより背が高く、上へはみ出します)。追加の絵は「画素譜」の仕様どおりのファイル名で `assets/` に置けば、コード側の変更なしで反映されます。

- **フィールド/街/ダンジョン**:現在は色面(緑=草原、茶=街道、灰=ダンジョン床、深緑=木立、灰褐=岩壁、茶=建物 など)で描画しています。「地誌譜」の画像生成プロンプトで作ったタイル絵に差し替える場合は `js/engine/renderer.js` の `drawMap()` を画像描画に置き換えるだけで反映されます。マップの形状自体(`js/data/maps.js`)はそのまま使えます。`maps.js` の各マップは `art` にタイルの絵をそのまま持ち、絵の中の数字が宝箱・人物の目印になっているので、形を描き替えても座標を数え直す必要はありません。
- **キャラクター**:戦闘・フィールドともに色付きの丸/パネルで表現しています。「群像譜」の立ち絵をスプライトとして描画する場合も、`renderer.js` の描画部分を差し替えるだけで済む構造です。
- **音楽**:効果音・BGMの再生は未実装です。「楽団譜」で用意したSUNO生成曲を音声ファイル化したら、`Game.Core` のモード切替(タイトル/フィールド/戦闘)のタイミングで `Audio` 要素を鳴らす処理を足すだけで組み込めます。

## テストについて

Playwright(Chromiumヘッドレス)で、タイトル→全16章→エンディングまでを自動移動・自動戦闘で通しプレイする検証を行っています。検証中に発見した「メッセージウィンドウを閉じた同じフレームの決定キー入力が、メニュー開閉やコマンド選択に二重に使われてしまう」というタイミングバグは修正済みです。

マップは形を描き替えるたびに、**入口から門・ボス部屋・宝箱・店・人物のすべてに歩いて辿り着けるか**を幅優先探索で検査しています。また「歩けるのにどこからも行けない浮き島」が残っていないことも同時に確認しています。

## 今後の拡張候補

### 章の分岐選択(アイデア段階・未実装)

現在は全16章とも一本道ですが、シナリオ資料集には分岐が想定されている場面がいくつかあります。実装するなら以下が候補です。

| 章 | 分岐 | 結果の差 |
|---|---|---|
| 第五章 | ガロズを **討伐する / 投降を受け入れる** | 投降ならガライとして後に加入、討伐なら第十章の反乱の展開が変わる |
| 第九章 | バロウズを **疑う / 善意の聖職者として受け入れる** | 終章までの伏線の見え方(プレイヤーがどこまで真相に近づけるか)が変化 |
| 第十章 | ガライを **信じる / 貴族の要求を飲んで退ける** | 退けた場合はガライが仲間にならず、パーティが3人のまま |
| 第十一章 | ヴァンスを **力づくで止める / 説得を試みる** | 終章での彼の描かれ方が変わる |

実装の要点:
- `js/data/chapters.js` の stage に `choices: [{label, next}]` を持たせ、`Game.Story` に選択待ちの view を足す
- 選んだ結果を `Game.Story` のフラグとして保持し、`Game.Save` の `story` に含めて保存する
- 分岐によって `onComplete.recruit` の有無が変わるため、パーティ人数に依存するボス調整(`js/data/monsters.js` のコメント参照)を見直す必要がある
